# Insurance Financial Endorsement & Adjustment Taxonomy
# تصنيف الملحقات والتعديلات المالية للتأمين

> **Financial Action / إجراء مالي**
>
> - **Yes / نعم:** The item directly changes premium, refund, debit, credit, commission, installment, invoice, or another policy financial movement.
> - **No / لا:** The item is primarily administrative, underwriting, coverage, claims, or data-related and does not inherently create a financial movement.
> - **Conditional / مشروط:** A financial action is required only when the insurer's configured rating/pricing rules produce a financial impact.
>
> **Important:** The classification below indicates whether the **type normally requires a financial action**. The actual financial calculation must always follow the insurer's configured rules, rates, effective-date conventions, taxes, fees, commissions, minimum premiums, and other applicable settings.

# IV. Financial Action Classification Rules
# رابعاً: قواعد تحديد الإجراء المالي

## 1. Yes / نعم

A **Yes** classification means the endorsement or adjustment is normally expected to generate a financial movement, such as:

- Additional premium / قسط إضافي
- Return premium / رد قسط
- Debit adjustment / تسوية مدينة
- Credit adjustment / تسوية دائنة
- Invoice creation or adjustment / إنشاء أو تعديل فاتورة
- Installment adjustment / تعديل قسط/دفعة
- Commission adjustment / تعديل العمولة
- Tax or fee adjustment / تعديل الضرائب أو الرسوم
- Recovery receivable / مبلغ مستحق للاسترداد

## 2. No / لا

A **No** classification means the transaction is normally administrative or informational and does **not inherently create a financial movement**.

Example:

**Beneficiary Change / تغيير المستفيد**  
Normally changes policy data only and does not change premium.

## 3. Conditional / مشروط

A **Conditional** classification means the endorsement **may or may not** create a financial movement.

The system must evaluate the insurer's configured rules before deciding whether to create a financial transaction.

Examples:

- Data Correction / تصحيح البيانات
- Benefit Limit Amendment / تعديل حدود المنافع
- TPA Network Tier Amendment / تعديل مستوى شبكة TPA
- Named Driver Addition / إضافة سائق مسمى
- Deductible Amendment / تعديل التحمل
- Exceptions / الاستثناءات

A conditional item must **not automatically receive a default premium, rate, refund, fee, tax, or commission value**.

# V. System Design Rule
# خامساً: قاعدة تصميم النظام

> **The insurer's configured values are the source of truth.**
>
> **قيم شركة التأمين المُهيأة داخل النظام هي المصدر الوحيد للحقيقة.**

The system must not hard-code default financial values for endorsement calculations.

The insurer configuration should determine, as applicable:

- Rating method / طريقة التسعير
- Premium rate / معدل القسط
- Pro-rata method / طريقة الاحتساب النسبي
- Effective-date rules / قواعد تاريخ السريان
- Month calculation method / طريقة احتساب الشهر
- Minimum premium / الحد الأدنى للقسط
- Short-period rates / أسعار المدد القصيرة
- Refund rules / قواعد رد الأقساط
- Taxes / الضرائب
- Fees / الرسوم
- Commission / العمولة
- TPA fees / رسوم TPA
- Cancellation rules / قواعد الإلغاء
- Reinstatement rules / قواعد إعادة التفعيل
- Rounding rules / قواعد التقريب
- Currency / العملة
- Any insurer-specific financial rule / أي قاعدة مالية خاصة بشركة التأمين

If the insurer has not configured a required value or rule, the system should **not invent a default value**. The required configuration should remain empty and the system should require the insurer/user to configure it before performing the affected financial calculation.

إذا لم تقم شركة التأمين بإعداد قيمة أو قاعدة مطلوبة، فلا يجوز للنظام **اختراع قيمة افتراضية**. يجب أن تظل خانة الإعداد المطلوبة فارغة، وأن يطلب النظام من شركة التأمين/المستخدم إعدادها قبل تنفيذ الحساب المالي المتأثر.

# VI. Financial Action vs. Policy/Claims Action
# سادساً: الإجراء المالي مقابل إجراء الوثيقة/المطالبات

| Category | English | العربية | Financial Action |
|---|---|---|---|
| Financial Endorsement | Changes policy/member/asset terms with financial impact | تعديل في الوثيقة/العضو/الأصل ينتج عنه أثر مالي | **Yes / Conditional** |
| Non-Financial Endorsement | Changes policy information without financial impact | تعديل بيانات الوثيقة دون أثر مالي | **No** |
| Claims Financial Adjustment | Adjusts money related to a claim | تسوية مالية مرتبطة بالمطالبة | **Yes / Conditional** |
| Claims Exception | Special approval of normally excluded/restricted treatment | موافقة استثنائية على خدمة مستبعدة أو مقيدة | **Conditional** |
| Recovery | Amount to be recovered from a party | مبلغ واجب الاسترداد من طرف | **Yes** |
| Administrative Correction | Corrects information only | تصحيح بيانات فقط | **No / Conditional** |

# VII. Recommended System Behavior
# سابعاً: السلوك الموصى به للنظام

For every endorsement or adjustment type, the system should store at minimum:

| Field | العربية |
|---|---|
| Endorsement/Adjustment Type | نوع الملحق/التسوية |
| Line of Business | فرع التأمين |
| Individual/Corporate | فردي/جماعي |
| Financial Action Required | هل يتطلب إجراءً مالياً |
| Financial Action Mode | نوع الإجراء المالي |
| Effective Date | تاريخ السريان |
| Calculation Method | طريقة الحساب |
| Insurer Configuration | إعدادات شركة التأمين |
| Premium Impact | أثر القسط |
| Refund/Recovery Impact | أثر الرد/الاسترداد |
| Commission Impact | أثر العمولة |
| Tax Impact | أثر الضرائب |
| Invoice Impact | أثر الفاتورة |
| Approval Required | هل يحتاج إلى موافقة |
| Audit Trail | سجل المراجعة والتدقيق |

**Core rule / القاعدة الأساسية:**

> **An endorsement type defines the business event. The insurer configuration defines how the financial impact is calculated.**
>
> **نوع الملحق يحدد الحدث التأميني، بينما إعدادات شركة التأمين تحدد كيفية حساب الأثر المالي.**
